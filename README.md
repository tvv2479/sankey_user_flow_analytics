# Sankey User Flow Analytics
Аналитический проект по исследованию пользовательских путей, конверсионных воронок и перекрестных продаж (cross-sell) цифрового продукта с помощью интерактивной диаграммы Sankey в Plotly.

## Бизнес-контекст и задачи
Проблема бизнеса:

При запуске линейки продуктов (бесплатные паки, отдельные платные плагины ретуши Heal / Dodge & Burn, облачные решения и подписки) сложно отследить паттерны поведения пользователей после регистрации: кто ограничивается бесплатными предложениями, как плагины стимулируют покупку бандлов и какая часть аудитории переходит на регулярную подписку.

Цели проекта:

* Выявить зоны конверсии: Отследить путь пользователя от регистрации (Registration) до первичного целевого действия и глубокой монетизации.

* Анализ cross-sell эффектов: Оценить долю покупателей, объединяющих одиночные инструменты в комбо (Heal + Dodge).

* Оценка эффективности фримиум-модели: Определить конверсию пользователей, взявших промо-пак (Got Free Pack), в платные сервисы (Cloud / Subscription).

## Архитектура воронки пользователей
Исследование разбито на 3 последовательных этапа (Step-by-Step Flow):

```text
[Step 1: Registration]  ───►  [Step 2: First Action]  ───►  [Step 3: Deep Monetization]
      • Registration             • Got Free Pack               • Heal + Dodge (Bundle)
                                 • Heal                        • Cloud
                                 • Dodge & Burn                • Subscription
```


## Логика обработки данных (SQL CTE):
1. Базовый фильтр (base_users): Исключение технического IP (91.150.101.73) и нецелевых реферальных каналов (3dlutmobile app).

2. Step 1 — Регистрация: Первичная точка входа всех уникальных пользователей за период.

3. Step 2 — Активация: Первая покупка или получение бесплатного продукта (через оконную функцию ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY data_pay)).

4. Step 3 — Монетизация:

   - Анализ совокупных покупок: если клиент купил и Heal, и Dodge & Burn, ему присваивается приоритетный статус Heal + Dodge.

   - Категоризация регулярных платежей: подписки (Subscription) и облачные функции (Cloud).

5. Агрегация Sankey: Финальное объединение состояний по парам source → target с подчетом уникальных пользователей COUNT(DISTINCT user_id).

## Стек технологий
* Database Engine: PostgreSQL

* Data Extraction & Transformation: SQL (Common Table Expressions, Window Functions, Aggregate Logic)

* Programming & Analytics: Python 3.10+, Pandas

* Visualization: Plotly (plotly.graph_objects.Sankey)

* Database Connection: SQLAlchemy 2.0, python-dotenv

## Пример выводов по анализу (Key Takeaways)
1. Активационный драйвер: Бесплатные паки (Got Free Pack) привлекают наибольшую массу пользователей на 2-м этапе и выступают главным мостиком к регулярным сервисам (Cloud и Subscription).

2. Синергия продуктов Heal & Dodge: Пользователи, купившие один из плагинов ретуши, с высокой долей вероятности докупают второй, формируя сильный бандл-сегмент (Heal + Dodge).

3. Оптимизация воронок: Прямые конверсии из единичных плагинов в подписку без прохождения промежуточного этапа минимальны, что указывает на необходимость доработки таргетированных push/email-кампаний.
